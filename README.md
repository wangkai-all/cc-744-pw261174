# 零件清算台 · 多品种组合拍卖

一个完全在浏览器内运行的**多品种零件拍卖清算演示**。所有订单、企业名称和金额均为虚构，清算点不连接任何真实资金账户，也不发起任何外部网络请求。

页面输入报价 → 冻结报价并求最大交易剩余 → 形成真实成交明细 → 用逐报价反事实（VCG）计算支付/收款。

## 运行

```bash
npm start          # http://127.0.0.1:4173
npm test           # 23 个引擎测试（Node 内置 test runner）
```

无需构建步骤，无第三方运行时依赖：原生 ES modules + 静态服务。

## 机制

- **组合报价**：一条买方报价是一个必须整组获得的品种/数量组合（`atoms`），并带申报价值上限。
- **替代组**：同一买方的多条报价可共享一个 `altGroup`，至多成交一条。
- **预算**：买方预算按申报价值占用（不是按支付额），清算时同时校验。
- **分段供给**：每个卖方按品种、数量和单价提交分段；同一品种按单价升序取用，最后一段可部分使用。
- **赢家确定**：买方报价 ≤ 16 条时对全部子集精确枚举，取福利最大者。并列时依次按 福利 → 申报买方价值 → 报价编号字典序 决胜，所有并列方案都会列出。
- **支付（VCG 逐报价反事实）**：对每个赢家报价单独撤除后重新求最优分配：
  `payment = W(−b) − (W − v)`；供应商收款 `receipt = W + cost − W(−s)`。绝不用"最后一笔成交价"或统一价代替。
- **资金缺口**：预算平衡不是机制的保证。页面单独披露 `卖方收款合计 − 买方支付合计` 的缺口，**不调整支付去凑平**。
- **全有或全无**：主问题 + 全部反事实子任务共享一个枚举节点预算。任一子任务失败或超时，`settlements` 为 `null`，不发布只有部分赢家支付的结算单。
- **轮次**：清算开始即冻结报价。冻结后的撤单/改供给进入下一轮待生效清单，可采纳供给对比结果作为下一轮变更。

## 内置场景

| 场景 | 用途 |
| --- | --- |
| 组合 · 替代 · 预算 | 基准小市场：组合、替代组、预算、未成交报价、未使用高价分段 |
| 未成交 | 所有申报价值低于采购成本，福利为 0，不发布任何条目 |
| 并列最优 | 两个福利相同的分配，展示决胜规则与全部并列方案 |
| 计算超时 | 共享节点预算 70,000 下主问题可解、反事实耗尽 → 拒发结算单（可调大预算重算） |

另可在侧栏勾选"演练：让第 2 个反事实子任务失败"来验证同样的拒发路径。

## 页面可交互项

- 点击任意买方/卖方报价：查看接受原因，或未成交的诊断（供给不足 → 联合供给 → 预算 → 替代组 → 被更高出价击败/并列落选）。
- 点击成交明细/卖方收款表任意行：打开该笔支付的反事实计算抽屉（W、W(−)、公式与替代最优分配）。
- 供给对比：修改任一分段的数量或单价，并排比较两轮的赢家、福利、成本与资金缺口；可将变更采纳为下一轮供给。
- 冻结后可撤回报价或修改供给，均记入下一轮。
- 草稿轮可录入新的买方组合报价与卖方分段供给。
- "独立暴力校验"：另写一套不共享求解器代码的子集枚举，复查福利与分配。
- 导出结算 JSON。
